## 插件与版本

界面语言由上游 i18next 与设备偏好统一控制，支持简体中文、英语、繁体中文、西班牙语、法语、德语、日语和韩语，切换后整页刷新。`supdance-i18n` 1.3.0 保留既有专属词条、自定义覆盖、翻译管理和审核数据，并通过明确的管理键编辑上游界面、创作页和模型展示文案。旧 DOM 翻译和第二套插件语言总控不挂载到页面；法语和德语已有完整内置目录。后台入口为 `/admin/i18n/entries` 的「翻译更新中心」。公开 bundle 返回 `pluginVersion`，应用版本与插件版本分别维护。

后台写入失败保留草稿，不发布本地覆盖；成功后从服务器重新读取公开 bundle。删除覆盖恢复内置译文。完整目录导入最多 20,000 条，在同一事务中分批校验，任一批次失败都会回滚。既有翻译、审核、锁定和历史发布不因语言扩展而重置。构建期静态 UI 文字处理及发布边界见仓库 `docs/supdance/I18N_UNIFICATION.md`。

## 源码更新流程

在 `web/` 使用项目要求的 Bun 版本运行：

```bash
bun run i18n:scan
bun run i18n:draft
bun run i18n:check
```

扫描结果为 `.local/cache/i18n/scan.json`，默认草稿为 `.local/cache/i18n/drafts.json`。扫描识别 JSX 文本、界面属性、常见 UI 配置、通知调用和静态 `t()` 引用，保留源文件及行号。模板表达式使用变量占位符，但需要上下文确认，不直接自动收录。自定义渲染器、运行时拼接、用户内容和后端动态内容不能仅靠静态扫描证明覆盖。

与 `supdance/i18n/source-baseline.json` 比较后，报告新增、源文修改、唯一可识别的移动、疑似废弃、原文歧义、缺失 key 和旧译文失效。移动识别只接受上下文及源文均唯一的对应项；复杂重构保留人工判断。疑似废弃不自动删除。词库源文变化而译文 hash 未变时，CI 要求复核该语种。

既有未收录文案与静态引用误报保留为存量基线。新增问题不得通过提高预算隐藏。完成词条收录或明确审查例外后，显式运行 `bun scripts/i18n-scan.mjs --write-baseline` 并审核基线差异。基线更新不是翻译验收；发布前仍需真实路由检查。

每日上游工作流扫描目标 Release，上传差异报告和无付费翻译字段草稿；目标源码扫描为合并前提示。合并后的 CI 再对真实结果执行门禁。前端词库是内置翻译唯一源，`i18n-sync-backend.mjs` 直接加载模块并验证占位符和 URL 后生成后端词典，不再依赖引号、缩进或单行格式。

## 翻译记忆与可选模型补译

默认只生成字段，不发送模型请求。可通过明确指定的已审核词库 JSON 复用译文：

```bash
bun scripts/i18n-draft.mjs --memory ./reviewed-translations.json --limit 100
```

模型补译需要部署维护者在受控终端配置 `SUPDANCE_I18N_TRANSLATION_URL`（完整 HTTPS Chat Completions 端点）、`SUPDANCE_I18N_TRANSLATION_KEY` 和 `SUPDANCE_I18N_TRANSLATION_MODEL`。密钥不进入仓库、浏览器或草稿。术语与受保护名称来自 `supdance/i18n/glossary.json`。

```bash
bun scripts/i18n-draft.mjs --translate --max-source-chars 2000 --limit 20
```

`--max-source-chars` 是本次请求的源文字符上限，不是货币费用或 token 总额保证；实际账单取决于服务商。每次响应最多请求 4096 输出 token，不自动重试未知结果。每条完整成功的草稿原子写入检查点，重跑时复用同 key、同源文 hash 的结果。请求失败或结构校验失败必须显式报错；已完成检查点保留。首次处理存量可显式加 `--include-backlog`，批次最多 500 条。自动补译结果仍是草稿。

## 后台审核、发布与锁定

导入草稿 JSON 后，八种语言的内容与源码位置可在更新中心查看、编辑。导入不影响线上词库。草稿编辑会撤销原审核状态；八种语言齐全、占位符/URL 一致且源文版本未失效后才能审核，再发布所选词条。发布前有确认界面。

人工锁定词条不能通过草稿发布、原有编辑/删除/导入接口或回滚修改；管理员须先解锁。相同源文无法证明相同业务语义，翻译记忆同时考虑命名空间，不自动处理有歧义的原文。新 UI 推荐显式 key；上游页面直接使用原生 `useTranslation`；扩展使用显式 key，不通过 DOM 文字替换实现翻译。

发布历史保留最近十次完整的发布前覆盖快照。「回滚到该次发布之前」恢复该次发布前的全部自定义覆盖，并将回滚操作自身记入新历史；不删除内置词条。回滚前确认影响及发布后人工编辑，避免覆盖后续维护。历史快照只在服务端保存，不向公开 bundle 或后台历史列表发送。

已记录 `builtinSourceHash` 的人工覆盖在上游源文变化后显示待复核提示；旧版本覆盖没有这一元数据，不能自动证明是否过期，需要首次人工审查。

## API 与持久化

- `GET /api/admin/plugins/supdance-i18n/workflow`：管理员读取草稿、锁定项、历史摘要、失效覆盖提示与修订号。
- `POST /api/admin/plugins/supdance-i18n/workflow`：`action` 为 `stage/review/publish/discard/lock/unlock/rollback`，必须携带 `expectedRevision`；按操作提供 `drafts/keys/releaseId`。
- 工作流冲突返回 HTTP 409；字段或翻译校验失败返回 HTTP 400。鉴权与管理员权限沿用宿主合同。
- 复用 `system_settings` 的 `supdance_i18n_workflow`，同一 JSON 保存状态与历史快照；已发布覆盖仍为 `supdance_i18n_custom_entries`。不新增表、列或 schema 迁移。
- 发布、回滚、工作流与审计写入同一数据库事务；原有词条写路径也获取同一行锁。非法持久化 JSON 拒绝覆盖，不以空词库兜底。

公开 bundle 的 ETag 纳入内置词库及插件版本；客户端恢复焦点、联网、页面可见或每两分钟重新同步。服务端进程内缓存上限两分钟；多实例传播仍受该缓存周期约束。专属语言包加载失败保留源文并记录告警，不改变原生语言偏好。

## 发布与回退

按现有部署方式保留数据库、配置、旧二进制及静态资源，再升级应用。无 schema 升降级；回退旧二进制不会读取新工作流键，已发布覆盖仍是原有词条格式。应用回退与翻译内容回滚是两个独立操作。回退应用不会自动恢复覆盖，恢复内容应使用发布快照或部署前数据库备份。

验证应覆盖扫描与基线差异、词库键一致性、八语种完整性、占位符、权限、并发版本冲突、锁定、草稿隔离、审核发布、回滚和真实后台页面。模型替身或无付费草稿验证不能证明真实服务商补译成功。

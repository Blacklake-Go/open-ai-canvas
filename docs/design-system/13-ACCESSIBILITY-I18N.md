# 13 — 国际化与无障碍设计规范 (Accessibility & i18n Specification)

> **设计层级**：Layer 1 — Global Foundation  
> **适用范围**：全站所有交互组件、表单、提示、数据报表与导航系统。  
> **标准基准**：对齐 **WCAG 2.2 AA** 国际标准与 SupDance **六国语言**实时国际化系统。

---

## 1. 六国语言实时国际化规范 (i18n System)

SupDance 官方支持 6 种标准语言（由 `web/src/supdance/plugins/i18n/` 驱动）：
1. **`zh-CN`**：简体中文 (默认)
2. **`en-US`**：English (英语)
3. **`zh-TW`**：繁體中文 (繁体中文)
4. **`ja-JP`**：日本語 (日语)
5. **`ko-KR`**：한국어 (韩语)
6. **`es-ES`**：Español (西班牙语)

### 1.1 文本长度弹性设计原则 (Text Expansion Resilience)
- **西文字符膨胀定律**：西文（英文、西班牙语）与日韩文在翻译后，文本长度通常比中文**长 130% 至 220%**。
- **严禁写死固定宽度**：
  - 严禁在按钮、标签或表格表头上写死固定像素宽度（如 `w-[60px]` 或 `width: 72px`）。必须使用弹性布局（`min-width`、`flex-shrink: 0`、`auto`）。
  - 弹窗底部操作按钮容器必须支持换行或自适应拉长，禁止出现文字因宽度不足而被“…”粗暴截断甚至溢出按钮外框的丑陋现象。
- **严禁硬编码中文**：所有新增界面文案必须调用多语言词条体系，禁止在 JSX/TSX 中裸写业务中文。

### 1.2 数字、货币与时间国际化
- **数值与金额**：必须统一使用浏览器标准 API `Intl.NumberFormat` 进行本地化格式化（例如千分位 `,` 分隔）。
- **时间与日期**：使用 `dayjs` 结合当前激活 Locale 进行多语言渲染，支持相对时间展示（如“5 分钟前” / “5 minutes ago”）。

## 2. WCAG 2.2 AA 无障碍访问标准落地 (Accessibility)

### 2.1 色彩与文本对比度底线
1. **常规正文 (Normal Text)**：与背景的对比度必须 **≥ 4.5:1**。
2. **大文本 (Large Text, ≥ 18px 加粗或 ≥ 24px 常规)**：对比度必须 **≥ 3.0:1**。
3. **关键 UI 组件与边界**：输入框外框、开关滑块、图标按钮必须 **≥ 3.0:1**。
4. **禁用单纯靠颜色传达信息**：表单校验错误、任务成功或系统警告，必须辅以文字或图标徽章，色弱与色盲用户可无障碍识别。

### 2.2 全键盘可导航性 (Keyboard Navigation)
全站所有核心流程（从登录、模型配置、提示词输入、提交生成到成果下载）必须**仅凭键盘即可独立完成**：
- **`Tab` / `Shift + Tab`**：在可聚焦元素间依逻辑顺序前移/后移。
- **`Enter` / `Space`**：激活选中的按钮、勾选 Checkbox 或展开下拉菜单。
- **`ArrowUp` / `ArrowDown`**：在下拉列表、菜单项、单选组合中移动高亮项。
- **`Escape`**：关闭当前展开的弹窗、抽屉、下拉面板或提示层。
- **焦点指示器 (`:focus-visible`)**：键盘聚焦时呈现清晰的双层焦点光圈，严禁通过 `outline: none` 抹杀键盘指示。

### 2.3 屏幕阅读器与语义标牌 (ARIA Contract)
1. **纯图标按钮**：必须显式提供 `aria-label`（如 `<button aria-label="关闭弹窗"><X /></button>`）。
2. **状态切换控件**：必须具备 `aria-pressed="true|false"`（工具按钮）或 `aria-checked="true|false"`（开关）。
3. **表单错误关联**：输入框发生错误时，必须通过 `aria-invalid="true"` 与 `aria-describedby="error-message-id"` 将错误文本与输入框精准绑定。
4. **异步状态通知**：任务队列与进度变化区域添加 `role="status"` 与 `aria-live="polite"`，便于屏幕阅读器即时感知。

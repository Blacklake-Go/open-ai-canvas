# 04 — 管理后台专有视觉与布局设计规范 (Admin UI Specification)

> **设计层级**：Layer 3 — Application Design System (Admin Scope)  
> **适用路由**：`/admin/*` 全部管理后台子路由。  
> **核心定位**：管理后台是高密度、高效率的**运维与运营控制台**，不是创作者工作台。视觉规范与组件状态必须与前台及创作工作台彻底物理隔离。

---

## 1. 隔离边界与防火墙机制 (Isolation Contract)

1. **Token 隔离源**：
   - 管理后台使用 `web/src/pages/admin/theme/admin-tokens.css`。
   - 所有变量以 `--admin-*` 为唯一真值（例如 `--admin-bg`、`--admin-surface`、`--admin-border`、`--admin-text`）。
   - 作用域限定在 `[data-admin-root]`、`body.admin-overlays` 以及 `.admin-drawer / .admin-modal-root` 内部。
2. **主题配置隔离**：
   - 采用 `getIsolatedAdminAntTheme()` 生成专属 Ant Design Token。
   - **绝不读取前台创作者皮肤**，不复用 `getAntThemeConfig()`。
3. **动效隔离**：
   - 仅保留 `120ms` 的轻量颜色过渡，禁止页面入场位移大动画、卡片弹跳或粒子特效。

---

## 2. 页面骨架与三大经典原型 (Page Archetypes)

管理后台禁止为任何入口单独发明无规则布局，全站 20+ 个管理子页面严格归纳为以下三种页面原型：

### 2.1 列表型页面 (List-First Archetype)
- **典型应用**：用户管理 (`/admin/users`)、模型目录 (`/admin/models`)、渠道管理 (`/admin/channels`)、系统日志 (`/admin/logs`)、请求明细、兑换码运营。
- **布局层次**：
  ```text
  ┌────────────────────────────────────────────────────────┐
  │ 统一页头 (标题 + 路径分组 + 右侧主操作)                  │
  ├────────────────────────────────────────────────────────┤
  │ ListToolbar (搜索输入框 + 筛选下拉组 + 激活筛选标签 + 导出) │
  ├────────────────────────────────────────────────────────┤
  │ BatchActionBar (批量操作栏，仅在复选计数 > 0 时浮现)     │
  ├────────────────────────────────────────────────────────┤
  │ 表格容器 (固定表头，数据行内部纵向滚动，高度填满视口剩余) │
  ├────────────────────────────────────────────────────────┤
  │ PaginationBar (固定于卡片底部的分页条，高度统一 44px)   │
  └────────────────────────────────────────────────────────┘
  ```

### 2.2 设置型页面 (Settings Workspace Archetype)
- **典型应用**：站点外观 (`/admin/settings/appearance`)、运行策略 (`/admin/settings/runtime-policy`)、存储配置、邮件配置、功能开放。
- **宽屏双列自适应**：
  - **视口 ≥ 1600px**：采用“左侧主设置流 + 右侧固定摘要（约 344px）”双列布局。摘要卡以 2×2 指标展示服务端运行状态，随页面平滑滚动。
  - **视口 < 1600px**：自动收拢为“全宽状态栏 → 横向四格摘要 → 单列设置流”，禁止破坏输入区宽度或产生横向滚动条。
- **设置卡结构 (`SettingsSectionCard`)**：
  - 左侧约 `264px`：功能图标、业务标题、用途描述与当前状态指示器（垂直居中对齐）。
  - 右侧主控制区：表单网格、开关组、参数输入矩阵，与左侧说明使用同色基底，仅通过纵向 1px 发丝线隔离。

### 2.3 运营驾驶舱原型 (Dashboard Archetype)
- **典型应用**：数据概览首页 (`/admin`)。
- **首屏回答核心问题**：系统当前健康度、核心指标日变化、异常排队项。
- **四大核心健康域**：用户活跃、生成任务、服务质量 (P95/成功率)、估算费用。
- **趋势与关注联动**：在视口达到 `1280px` 时，左侧 280px 高度趋势折线图与右侧“需要关注（异常/阻塞）”列表按 2:0.82 紧凑排列。

## 3. 数据表格设计系统 (Admin Data Table System)

表格是管理后台的核心交互载体，必须严格遵守以下规范：

### 3.1 尺寸与密度
- **表头高度**：`36px`，背景为 `var(--admin-subtle)`，文字为 `12px` 中性加粗。
- **数据行高度**：统一为 `40px`，边框线为 `1px solid var(--admin-row-border)`。
- **单元格内边距**：水平 `12px`，垂直居中。

### 3.2 列对齐契约 (Alignment Rules)
- **左对齐 (Left-aligned)**：名称、用户账号、API 路径、标题、长文本等主识别列。
- **居中对齐 (Center-aligned)**：状态徽章、短类型、枚举标签、时间戳、IP 地址、操作按钮列。
- **右对齐 (Right-aligned)**：数值、金额、积分消耗、Token 数量、响应耗时（必须启用 `font-variant-numeric: tabular-nums`）。

### 3.3 表格内交互状态
- **行悬停 (Row Hover)**：底色变化为 `var(--admin-row-hover)`，过度时长 `100ms`。
- **行选中 (Row Selected)**：底色为 `var(--admin-selected)`，保持选中复选框对齐。
- **空数据状态 (`AdminTableEmpty`)**：展示统一 `SearchX` 图标、主标题、次要描述与“重置筛选”操作。
- **加载状态 (`AdminTableSkeleton`)**：禁止使用粗暴的全屏菊花转圈，必须使用 8 行结构化骨架屏匹配列宽。

---

## 4. 侧边栏与导航行为规范

1. **尺寸规范**：
   - 展开状态：宽度固定为 `224px`。
   - 折叠状态：宽度固定为 `64px`，仅保留居中图标与 Tooltip 提示。
2. **导航项状态表达**：
   - 激活态：使用强调弱底色背景与加粗字体，**禁止在左侧添加突兀的高亮色条（No Left Accent Stripe）**，严禁使用粗描边。
   - 分组标题：采用 `11px` (Micro) 弱化灰色文字，禁止使用树状连接虚线。
3. **顶栏独立主题切换**：
   - 每个管理子页面右上角必须包含独立的明暗主题切换纯图标按钮（Sun/Moon），间距与保存操作保持 `8px`，无需离开后台即可切换预览。

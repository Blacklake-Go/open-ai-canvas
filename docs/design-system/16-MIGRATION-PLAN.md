# 16 — 存量页面平滑迁移方案与实施路线图 (Phased Migration Plan)

> **设计层级**：Phase 5 — Execution Roadmap & Risk Management  
> **实施边界**：第一阶段以建立完整设计体系规范、设计变量、组件契约和非侵入式自动化门禁为终点。后续大范围业务页面迁移必须严格遵照本方案分批、受控、可回滚地推进。

---

## 1. 迁移阶段原则与红线约束

1. **业务零中断**：严禁在未充分验证的情况下批量改写线上业务页面。任何改造绝不得影响模型计费、积分结算、登录认证、支付流程与长轮询任务生成。
2. **渐进式替换 (Strangler Pattern)**：不搞“推倒重来”的大爆炸重构。以新设计组件包裹或平滑替换老旧组件，保持接口 Props 向后兼容。
3. **分批排序原则**：优先解决导致功能受损或体验阻断的 P0 问题，再解决组件重复的 P1 问题，最后优化微视觉与微动效的 P2 问题。

---

## 2. 三级迁移任务矩阵 (P0 / P1 / P2)

```text
┌────────────────────────────────────────────────────────┐
│  P0 紧急阻塞级 (功能层级缺陷 · 交互不可用 · 计费失真)    │
├────────────────────────────────────────────────────────┤
│  P1 结构统一级 (多头组件替换 · 下拉框统一 · 表格标准化)   │
├────────────────────────────────────────────────────────┤
│  P2 视觉精细化 (圆角阴影归一 · 微动效节奏 · 裸值清零)   │
└────────────────────────────────────────────────────────┘
```

### 2.1 P0 优先级：核心交互阻断与功能安全
| 任务编号 | 改造目标 | 现状缺陷 | 预期改造方案 | 回滚方案 |
| :--- | :--- | :--- | :--- | :--- |
| **P0-01** | **弹窗内嵌下拉截断修复** | Modal 内打开 Select 时面板被 Modal 边框裁切或 Z-Index 错位 | 为内嵌下拉配置 `--z-dialog-popover` (1100) 并强制 Portal 至 `document.body` | 降级为原生 `<select>` |
| **P0-02** | **假进度条全面退场** | 部分生成任务使用前端计时器模拟假百分比，导致用户误判任务卡死 | 接入真实任务状态机 (`queued` / `processing` / `step X/Y`)，仅凭后端事件更新 | 保留带呼吸灯的耗时计时器 |
| **P0-03** | **后台外观同步首屏闪烁 (FOUC)** | 访客在自定义品牌下首屏偶尔闪现默认品牌与颜色 | 优化 `main.tsx` 中的 `bootstrapAppearance()`，保证元信息与 Token 首屏同步注入 | 降级为全屏安全加载骨架屏 |
| **P0-04** | **移动端软键盘遮挡主提交** | 手机登录或创作输入时软键盘遮挡“开始生成”按钮 | 配置 `interactive-widget=resizes-content`，按钮吸附至动态可见安全区 | 增加页面底部安全内边距 |

### 2.2 P1 优先级：核心组件标准化与重复消除
| 任务编号 | 改造目标 | 现状缺陷 | 预期改造方案 |
| :--- | :--- | :--- | :--- |
| **P1-01** | **下拉组件统一 (Select)** | AntD Select 与自研 Select 并存，样式与键盘行为不一致 | 完善 `components/ui/base/select/`（基于 RAC），支持搜索过滤与多选，优先替换工作台表单 |
| **P1-02** | **状态徽章统一 (Badge)** | AntD Tag、AdminStatusBadge 与 StatusBadge 三套方案 | 以 `StatusBadge` 为底层规范，提取标准成对 Halo/Dot 结构，Admin 保留高密度隔离引用 |
| **P1-03** | **管理后台数据表格对齐** | 部分管理页面表格列宽无固定、长模型名导致水平失控 | 全量落地 `admin-ui-design-standard.md`，左信息、中状态、右金额（开启等宽数字） |
| **P1-04** | **按钮尺寸与 Loading 标准化** | 异步按钮 Loading 时文字消失导致按钮瞬间变窄 | 全站推广标准 `IconButton` 与 `ToolButton`，Loading 态严格锁定外框物理宽度 |

### 2.3 P2 优先级：设计细节与微交互一致性
- **P2-01**：全面排查非核心页面中的硬编码 Hex 颜色，替换为 Semantic 变量。
- **P2-02**：圆角统一为 4/8/12/16px 四档，清除遗留的 `rounded-[7px]`、`rounded-[9px]`。
- **P2-03**：微动效对齐统一时长（80–120ms 点击，150–220ms 展开），且全面接入 `prefers-reduced-motion`。

## 3. 安全回滚与发布前双重验证机制

每一批次 UI 迁移必须严格满足以下条件方可上线：
1. **测试用例守护**：
   - 运行前端全部专项测试：`cd web && bun test`。
   - 运行设计系统门禁测试：`cd web && bun test test/design-system-compliance.test.ts`。
2. **无代码回滚方案**：
   - 高风险页面优先置于特性开关（Feature Flag）守护下，一旦发现线上异常可直接通过后台 `/admin/settings/features` 秒级关闭回滚，无需紧急重新发布版本。

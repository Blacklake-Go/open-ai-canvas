# 独立插件架构
插件 ID 为 `supdance-visual-engine`，发行版本 2.0.1，配置 Schema 2。V2.0 是产品代际，插件补丁版本与配置发布版本分别管理。

## 模块边界
前端所有配置、16 个控制台面板、主题、动效、恢复动画、API、存储与生命周期集中在 `web/src/supdance/plugins/visual-engine`。后端校验、迁移、权限与生命周期策略集中在 `backend/internal/supdance/visualengine`。Manager 通过 Repository、RequireAdmin 与 ID 生成器三个端口接入宿主；不导入 app 或 service。app 文件只负责组合这些端口和转发，handler 负责 Cookie 身份、JSON、体积限制和信封；repository 负责事务及数据库实现。

宿主挂载点登记于 `web/src/supdance/adapters/compatibility.ts` 与 `supdance/config/baseline.json`。新增主题/浮层扩展是有清理函数的显式注册；认证只增加展示 fallback 与已脱敏诊断事件订阅，不替换登录、跳转、任务、积分或支付流程。

## 生命周期
后台插件管理复用现有平台可用性开关，另提供安装、升级、卸载及健康检查。首次内置旧版状态按已安装 2.0.0 读取；升级到 2.0.1 前保存命名空间迁移备份。失败通过事务保留旧配置。卸载会移除活动注册、导航、样式所有权、Router/主题/浮层订阅、动画及轮询；按选择保留或清理主题、草稿、快照和迁移备份。管理员权限与审计保留。

这是随宿主构建分发的内置独立模块：在线安装管理的是已经交付的模块注册与运行资源；发布新代码仍需构建宿主。卸载不擦除不可变宿主二进制或浏览器模块缓存。源码包用于审查和构建集成，不能上传到通用 JavaScript 插件上传框执行。

## 配置与发布
服务端是唯一权威；每位管理员草稿独立命名空间。隔离预览不写站点根元素。发布采用预期 revision、草稿基线检查、数据库锁和条件写入，将配置、快照、草稿清理与审计放在同一事务。首次发布保留稳定基线，历史最多 50 个版本；回滚产生新的发布版本。已归档版本可比较差异并恢复。

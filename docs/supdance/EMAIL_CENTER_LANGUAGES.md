# 邮件品牌同步、八语言与页面管理

本轮在邮件中心候选提交 `26b351fc` 上继续开发，版本为 `1.2.0`，Schema 107。生产没有切换，没有修改 DNS，也没有真实外发。此前生产产物与提交之间的证据边界仍见 [邮件中心报告](EMAIL_CENTER.md)。

## 本轮需求与结构

- 邮件读取正式站点外观中的品牌。SupDance 品牌使用与站点页脚相同的 `supdance-footer-logo.png`，邮件模板按原比例显示，并通过内容哈希地址公开图片。其他品牌继续读取各自的外观 Logo。
- 用户持久化语言，账户邮件与获明确订阅的营销邮件按收件人语言发送。
- 简体中文 `zh-CN`、英语 `en-US`、繁体中文 `zh-TW`、西班牙语 `es-ES`、法语 `fr-FR`、德语 `de-DE`、日语 `ja-JP`、韩语 `ko-KR`，与站点原生语言列表一致。
- 原 `supdance-compact-model-picker` 插件保留 ID，显示名称改为「页面管理」，统一承载模型展示、HTML 页面与邮件中心三个分区。原有模块和权限继续复用。

职责边界：`maillocale` 管理纯语言规则与文案，`emailcenter` 管理事件合同和渲染，`emailtpl` 管理 MIME 正文母版与真实消费报告，auth 管理收件人语言选择及原认证流程，app 管理版本、品牌与活动，repository 管理增量字段和原子偏好写入。页面管理只是管理入口的聚合，不复制 HTML 页面或邮件数据。

## Logo 与品牌更新

发送、测试和服务端预览均重新读取 `system_settings.appearance` 与正式外观资源。Logo 以实际图片内容哈希保存，新的站点图片对应新的公开 HTTPS 地址，匿名读取不需要 Cookie 或临时签名。已发邮件保留其当时的素材版本，历史图片不因更换站点 Logo 而失效。

站点允许 PNG、JPEG 和 WebP。PNG/JPEG 使用原始图形；WebP 使用既有图像库转换成 PNG，保留尺寸、比例、透明度与图像内容，以适配邮件展示。转换有像素和大小上限，异常资源明确失败，不伪造替代 Logo。

后台通过独立的品牌元数据 API 核对更新：外观状态变化、返回窗口时，以及可见页面每 30 秒自动检查。只替换品牌状态并重新预览，不覆盖正在编辑的草稿。品牌核对失败显示错误；正式发送继续由服务端读取，不依赖浏览器缓存。轮询不反复读取联系人，也不制造邮件记录访问审计。

本轮再次匿名读取正式站点 Logo 得到 HTTP 200 / PNG，SHA-256 为 `62345460d5fa7b8f23640aede203da6b86e1f7eb9e4cf67d020427b1a707f233`。没有将该地址或本次版本查询参数硬编码进模板。

## 用户语言与发送选择

`users.preferred_locale` 保存明确的原生语言代码；旧账号保持空值，不伪造既有偏好。个人设置和联系人偏好分区提供用户语言选择。站点语言菜单保存到当前账号后再切换；写入失败会显示错误。已有账号在新设备登录时恢复保存的语言，旧账号首次进入界面时建立当前界面语言偏好。

前端写入按账号隔离并串行处理，避免初始化与用户主动选择互相覆盖，也避免异步响应污染切换后的账号。语言变更不会自动订阅营销邮件。

服务端选择顺序为：

1. 业务已固定的本次渲染语言，例如实际报告或活动已经选定的版本。
2. 收件账号保存的用户语言。
3. 独立营销联系人的已记录语言。
4. 匿名认证请求携带的当前界面语言或浏览器语言提示。
5. 站点默认语言，最终兼容既有 `zh-CN` 默认值。

显式保存只接受八种规范代码；浏览器语言提示支持地区匹配与权重，例如 `fr-CA` 对应 `fr-FR`、`zh-Hant-HK` 对应 `zh-TW`，不支持的提示不会阻断后续有效语言。已保存账号偏好不会被匿名密码重置请求的提示改写。

注册验证码、密码重置、统一验证接口，以及第三方账号入站补邮箱接口均传递语言。邮箱变更、旧邮箱通知和消费日报从原业务的账号上下文读取语言。验证码仍由服务端产生，保持原随机性、真实有效期、冷却、重放限制和会话绑定，语言不成为新的认证依据。

## 八语言内容与版本

11 个稳定事件各有八种内置模板，共 88 个事件/语言组合；事件 key、变量 schema 与类别保持稳定。主题、摘要、正文、受保护验证码说明、真实有效期、安全提示、测试标记、分类页脚和退订页面均有八语言版本。

消费日报还覆盖统计标签、星期、洞察、金额分隔与纯文本；只改变展示，保留 UTC+8 的统计口径、原始微积分数值、取整、账务计算与订阅条件。用户名称、模型标识和真实业务输入保留原文。元数据长度按 Unicode 字符校验，展开变量后再次限制长度。

模板以 `(key, locale)` 独立维护草稿、发布指针与历史版本。初始化可重入，保留现有中文自定义版本与旧 HTML 原文，不把旧 HTML 当作可执行翻译模板，也不覆盖运营已保存内容。其他语言建立相应内置版本。页面切换语言时隔离旧语言的编辑状态，旧响应不能覆盖新选择；跨语言发布历史版本会被拒绝。

营销活动创建时固定八种已发布模板版本，发送前读取收件人语言和最新订阅/抑制状态。周报的 `update_title`、`update_body` 必须通过 `variablesByLocale` 明确提供八语言内容；不以预览样例或同一份中文内容自动兜底。通用个人名称等数据仍通过 `variables` 传递。模板和变量不自动产生积分、优惠或权益。

旧单语言活动保留原数据与原发布版本，不静默替换为其他语言的新模板；缺少对应语言固定版本时拒绝发送，应审查后创建新的活动。语言不进入发送意图唯一键，修改语言不能重放同一次事件或已提交任务。

站点已保存的品牌名、自定义页脚、历史 HTML、用户输入和运营正文不是界面词条，不自动改写其源文；本轮提供的是内置邮件与编辑器的完整八语言文案，以及明确的分语言运营内容合同。

## 页面管理与旧地址

新入口为 `/admin/plugins/page-management`，`page` 查询参数选择 `models`、`html` 或 `email`。三个分区复用真实组件、路由状态、服务与管理员校验。模型展示原开关、画廊合规锁及发布规则不变；聚合入口不替其他模块开关授权，也不让账户安全邮件依赖营销插件的个人安装状态。

以下旧地址保留参数并跳转到聚合入口：

| 旧地址 | 新分区 |
| --- | --- |
| `/admin/plugins/compact-model-picker` | `page=models` |
| `/admin/plugins/html-pages`、`/admin/html-pages` | `page=html` |
| `/admin/plugins/email-marketing`、`/admin/email-center` | `page=email` |

邮件 `section`、`emailLocale` 等查询参数继续保留。内嵌发送记录使用 `logPage`，独立发送记录页继续使用 `page`。SMTP 设置页与发送记录原地址仍可访问，插件列表和后台导航指向统一入口。页面内部切换沿用路由拦截，未保存内容由原编辑器确认。

## API 与增量迁移

- `GET/PUT /api/auth/email-center/language`：读取有效语言，或提交 `{ locale }`。写入目标只从当前登录用户确定，不接受另一个用户 ID。
- `GET /api/admin/email-center/overview?locale=ja-JP`：读取所选语言的 11 个事件，同时返回 `supportedLocales`。
- 模板 draft/publish/preview/test 请求增加 `locale`，每次写入校验语言归属与乐观锁。
- `GET /api/admin/email-center/brand`：管理员读取最新公开品牌元数据，`no-store`，不返回联系人或密钥。
- 营销活动增加 `variablesByLocale`；数据中保存八语言版本映射和明确的各语言内容。
- 退订链接增加允许的 `lang`，GET 不退订，POST 直接退订；语言不会影响令牌用途校验、订阅范围或登录要求。
- 发送收据增加 `locale`，与模板、品牌版本和 SMTP 结果一起追溯，不保存验证码或正文。

Schema 107 仅增量添加用户语言、联系人语言、收据语言、活动多语言版本及变量字段；不重建用户表，不重置账号、SMTP、模板、日志、订阅或抑制。原 1–106 迁移身份和校验和保持不变。SQLite 与隔离 PostgreSQL 保留测试均通过，包括重复执行。

迁移仍使用 `tools/supdance/email-center/migrate.sh status|up|verify`，显式提供数据库驱动与目标连接。生产恢复库迁移及上线未执行。旧 Schema 106/105 程序不能直接连接 Schema 107；回退需使用支持 107 的构建，并保留新增偏好、版本、收据、退订和审计，不回放已处理事件。

## 验证边界

本轮自动化包含八语言词库及格式参数完整性、88 模板渲染、八语言真实本机 SMTP MIME、匿名注册/第三方入站语言、收件人偏好优先级、语言切换不重发、版本隔离、原认证规则、实际报告数据、Logo 变更与 WebP 图像保留、SQLite/PostgreSQL 增量迁移、编辑器八语词条、设计系统和插件隔离。

页面联调用独立合成数据与真实 React 路由。主机 Docker/Redis 超时后使用独立 SQLite 夹具，临时启动器只省略与邮件无关的大型知识库导入；不省略本轮实际邮件、权限、模板、用户语言或页面管理代码。最终前端构建与正式后端入口构建均通过，构建页面完成语言持久化/失败提示、草稿保护、Logo 自动替换与移动端亮暗主题检查。精确结果与聚合测试超时边界见 [本轮验证记录](EMAIL_CENTER_LANGUAGES_VALIDATION.md)。

没有真实外发、Gmail/Outlook/Apple Mail/QQ/163 实际收件或客户端渲染验收；翻译没有原生语言人工审校。生产发布、DNS、企业邮箱用途与额度、真实收件头和正式活动启动仍待独立授权。

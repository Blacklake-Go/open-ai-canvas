# 上游 v1.8.7.1 源码集成

以自有主线 `0819fcee1b33c4970c110e1081997eca1eef863a` 为基线，合入上游正式标签 `v1.8.7.1` 和同一提交的上游 main `882a1d1a50523fe992831e2b0da69f44b4469835`。集成版本为 `v1.8.7.1-supdance.3`。

## 二开保留

- `supdance/plugins/` 目录的七份插件清单和源码保持原样。音乐及 Mureka 素材归档、页面管理、邮件、社交登录、八语言、Waffo、工作流助手以及 Codex 入口沿用原插件身份。
- 通用模型测试继续将支持的音乐模型引导到带报价和结算的专用测试入口。音乐异步回查保留可重试错误处理和历史渠道别名，其他模型沿用上游入队时锁定的协议发行版。
- 团队账务保留上游的付款账户与封顶前用量，同时保留 SupDance 一小时缓存写入用量。创作页保留个人空间的音乐入口，团队空间沿用上游模式限制。
- 保留画布工作台的语言入口、Codex、时间线、小组空间路由及灵感展示资格和本地化。上游新增团队及模型设置文案仍需八语审校。

## 数据库

本站 Schema 1–108 的编号、名称和校验和沿用原版本。上游 106–109 分别映射为 109 团队空间及积分账户、110 公司与小组、111 共享工作区内容、112 模型协议版本。官方素材独立账本保持 4。

上线前需用备份恢复副本验证 `migrate-schema up` 和 `migrate-schema verify`，同时核对个人积分余额、冻结金额、个人历史订单、素材引用及已安装协议包。插件归档与 `.settings-key` 应随数据目录备份。账本升级后，旧 108 程序不能直接连接 112，回退需结合同一时间点的数据库与数据目录。团队开关缺省关闭。

## 本地验证

- Bun 1.3.9 下，前端类型检查、生产构建、八语静态词条覆盖、前后端词典一致性通过。创作词条、画布素材弹窗、语言与字典的最终组合为 36 项通过。社交注册恢复、画布工具栏、积分图标及插件架构专项为 23 项通过。音乐、页面管理、邮件、团队接口和界面规范的组合测试中有一项画布弹窗在 15 秒内未完成，随后使用原测试入口重跑通过。
- 后端音乐、协议发行版、团队、结算、Waffo 与 SupDance 相关专项通过。用 Go 1.25.14 复测画布 HTTP 诊断和 Agent 回归通过，Pi 运行时 18 项通过。第一次全量后端测试在本机 Go 1.27 下遇到运行时依赖缺失、诊断字段格式变化及应用测试组超时，后续以分项复测为准。
- 在隔离的 SQLite 与 PostgreSQL 测试库中执行 108→112、重复迁移和版本校验。两个数据库的原 108 条迁移账本逐条一致，独立官方素材账本保持 4。团队迁移对个人可用额度、冻结和账本的验证，以及邮件历史保留测试，两种数据库均通过。
- 原文巡检仍列出 51 处待确认项，涉及动态文案识别、部分工具提示及提示词业务占位符。新增译文需人工审校。生产数据恢复副本、真实浏览器视觉验收、认证平台和实付订单属于后续发布验收范围。

## 发布候选复核

复核原文巡检的 51 项。28 处已有编译阶段的八语词条，22 条工具和界面说明补入词库，视频复刻中的一个提示词引用标识保留原文。逐项处理见 [复核清单](../../supdance/i18n/upstream-20261120-review.json)。新增译文仍可做人工审校。

生产数据库的备份在专用恢复库中执行 108→112、重复执行及版本校验，173 张原表的原有列行数和摘要一致。主积分余额、冻结及历史账本随上述原列比对；新增团队账户键按迁移程序填写。恢复演练仅运行迁移命令。

发布标签 `v1.8.7.1-supdance.1` 的云端回归发现模型编辑版本时间精度在 PostgreSQL 中与保存响应不一致。后续版本仍保留严格并发校验，保存事务内读回实际持久化的时间，再交给编辑器。

发布标签 `v1.8.7.1-supdance.2` 启动时被请求协议包的内容校验拦截，切换脚本恢复了旧版服务和 Schema 108。上游同时变更了 19 个官方请求协议包的内容并沿用旧版本号。后续版本为这些包分配独立的 SupDance 修订号，保留已安装旧版本和摘要，以便继续解析历史模型引用。修订包已用生产插件登记副本和只读历史包在断网容器中启动后端，19 个旧协议发行版均已保留。正式新镜像上线前重复验证同一路径。

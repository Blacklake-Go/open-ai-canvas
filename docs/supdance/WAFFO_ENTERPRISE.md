# Waffo 企业版沙盒

本扩展使用 `github.com/waffo-com/waffo-go/v2 v2.3.0`，通过既有支付 RPC 运行时提供一次性充值收银台。与 Pancake 的商户、凭据和渠道配置分别管理。

## 边界

- 仅 `SANDBOX`，生产配置会明确拒绝，正式上线问题仍待确认。
- `allowedUserId` 在渠道列表、下单服务和插件中共同限制测试账号。普通用户不能通过直接提交渠道 ID 绕过限制。
- `WEB` 整页跳转，由 Waffo 显示支付方式。商品价格与积分来自宿主商品快照；结算币种配置为 USD，复用宿主既有汇率换算。
- 真实用户 ID、邮箱、商品名称和公开价格页传给 SDK。密钥存入宿主加密配置，不进入清单、日志、前端或文档。
- 退款、订阅、账单下载和真实收款尚未接入。

## 资金与状态

商户订单号在外部请求前落库，同时作为不超过 32 字符的 `paymentRequestId`。下单结果未知时，以同一请求号查单，不生成新订单。查询仍未知时保留待确认状态，由原订单后台轮询恢复。

收银台返回的 `acquiringOrderId` 提前绑定到 `provider_trade_no`；通知和查单证据须匹配交易号、订单号、实收金额与币种。通知还校验商户、测试用户和 `ONE_TIME_PAYMENT`。SDK 校验原始报文签名后，宿主加密保存持久通知收件箱，再返回 SDK 生成的 `X-SIGNATURE` 和原样 JSON 应答。通知重试由唯一事件键与原有账本事务保证一次发放；回跳不发权益，取消须查单确认终态。

## 宿主接缝

支付 SDK 增加可选的 `UserID`、`UserEmail`、`ProductID`、收银台交易号及通知签名应答，不改变旧插件必填字段。HTTP handler 仅转发严格校验的成功 JSON 与签名字段。数据库复用既有字段，无迁移。

## 构建与验证

`supdance/plugins/supdance-payment-waffo-enterprise/build.sh` 生成 Linux、macOS、Windows 的 amd64/arm64 包。专项测试覆盖 SDK 请求签名、通知验签、应答签名、用户隔离、金额精度、取消未知状态、提前绑定交易号和既有账本幂等。

`.waffo/integration-manifest.json` 记录当前验证范围。普通 validator 通过只说明机械约束满足；真实收银台、回调投递、失败支付和设备钱包完成前，不生成正式 Waffo 接入报告。另一台电脑应使用指定测试账号，在充值弹窗中选择 `Waffo Enterprise Sandbox`，只使用 Waffo 沙盒测试卡。

本站已安装 v1.0.1，并保存与插件版本匹配的渠道配置。沙盒经确认使用 `1 USD = 7 CNY`，例如人民币 10 元商品实际测试结算 1.43 美元。真实项目入口已完成 Visa 成功、拒绝、主动查单和主动取消，PostgreSQL 账本确认成功单一笔权益、失败单零权益，Waffo 后台确认通知投递成功。其余银行卡、设备钱包和实际重复通知尚未全部验收；不据此启用正式环境或生成完整官方验收报告。

部署采用当前生产镜像追加宿主二进制的增量镜像，保留已有 Agent、运行时与插件依赖。生产使用 PostgreSQL，交叉编译宿主的 SQLite 部署兼容性尚未验收；未来受管镜像发布需通过原 Dockerfile 的 CGO 构建。回滚先停用企业版渠道，再恢复部署前镜像和配置，不回滚已发生的支付账本。

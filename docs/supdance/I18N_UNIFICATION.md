# 国际化引擎与翻译管理

## 唯一语言状态

界面统一使用上游 `web/src/i18n` 的 i18next 实例与 `useLocaleStore`。支持简体中文、英语、繁体中文、西班牙语、法语、德语、日语和韩语。Ant Design、日期、绘图编辑器、法务及独立价格页按同一语言列表适配。旧语言偏好仅在设备尚未设置上游偏好时迁入一次；翻译插件设置和缓存更新不能改变设备语言。

`supdance-i18n` 继续提供词条管理、已有覆盖、自定义词条、草稿、审核、锁定、发布和回滚；不再负责第二套站点语言或运行时 DOM 翻译。历史 DOM 翻译工具保留兼容导出，但不挂载到产品页面。

## 词条和生效边界

- `upstream.<key>` 对应上游 `translation` 命名空间。
- `creation.<key>` 对应 `supdance-creation`。
- `model.<key>` 对应模型展示文案，不修改模型 ID、请求参数或计价。
- 原有 SupDance 词条及键保持不变。只有明确注册的管理键可以覆盖宿主资源；同名自定义键不能污染上游命名空间。
- `managedUi` 文案由构建期静态 UI 转换接入同一个 i18next。收集器只处理 JSX 文本、明确的展示属性、通知和内联选项标签；代码示例、保留原文区域、输入值、事件参数和普通对象字段均不转换。按文件作用域区分同一源词的不同用途。新增未登记文字会使构建失败。
- 后台成功写入后重新读取公开 bundle，使用服务器结果更新页面。请求失败保留编辑草稿，不产生本地“保存成功”。删除覆盖恢复内置目录。发布期间的旧客户端请求及服务端缓存填充不能覆盖新结果。

词条源位于前端目录；`web/scripts/i18n-sync-backend.mjs` 生成后端默认目录，不手工维护第二份译文。新增语言和缺失文字的机器辅助译文作为内置译文提供，并不冒充人工语言审校；后台仍可逐项审核和修订。

后端生成代码按固定大小的批次构建词条，再按原顺序拼接，避免完整目录集中在单个巨型函数中导致受限内存的 Go 发布构建失败。每次读取仍创建独立的词条和译文映射，不改变管理接口或译文内容。

## 导入和保护

完整目录导入最多 20,000 条，内部按 2,000 条分批校验，全部位于同一事务；后续批次失败时整次回滚。单次直接更新仍限 2,000 条。占位符（含中文双花括号模板）、花括号和 URL 必须保留，禁止译文额外注入标记。既有设置、覆盖、审核、锁与发布历史不做清空或重置。

本轮合入已在线的法务、价格页、页脚及登录页源码基线，扩充其语言，不调整价格数值、条款版本或生成合同。登录视频继续服从后台自动播放设置及系统减弱动效偏好。

## 验证与发布

提交前运行仓库推送门禁、完整词条同步与静态 UI 覆盖检查；专项验证已挂载 React 控件的语言切换、后台覆盖及删除、输入节点和用户输入保持、公开请求竞争、服务端缓存竞争和导入原子性。最终运行结果与生产发布证据写入发布记录。

发布不增加数据表或迁移。保留生产数据库备份、原后端镜像和前端目录；回滚只切换程序和静态资源，不恢复覆盖上线后交易的旧数据库。

# 音乐工作岛实现与回滚

## 来源和问题

实施基于生产 `065040500e3b48d9244ecfcb239b1223255a30dd` 对应的 `v1.7.4-supdance.7`，隔离分支从其后的 `origin/main@037b8ae94a2b822d9a06268031258bc3b25d8367` 创建。保留原工作区修改，生产仅进行配置、日志和原上游回执的只读检查。本候选没有生产发布。

旧工作岛使用静态四模型、独立网关密钥、按秒估算和独立音乐任务记录。通用模型测试器只展示创建响应，未把上游回执关联到持久任务、文件和账务。前端假设固定时长及格式，无法证明主站渠道实际可用。

宿主改动登记在 compatibility registry。`provider.go` 的别名二次解析只接受数据库中同一模型的上游 SKU，解决生成后下载阶段被误判模型不一致的问题，仍拒绝其他 SKU。

播放器通过通用 `data-workspace-bottom-bar` 标记和尺寸事件通知宿主浮动助手避让；不修改其持久位置偏好。共享资产卡片和详情保护用户标题原文。后台跨用户试听沿现有 `/api/admin/resources/:id/file` 管理员交付合同，普通用户继续使用所有权授权，不扩大普通资源接口权限。

## 请求和数据流

```text
登录用户 -> 音乐能力/主站报价 -> Music submit
  -> CreateTask(canvas_audio) + 事务预留
  -> RunningHub 专用协议 -> 保存 providerRequestId -> 分离轮询
  -> 媒体 checkpoint -> Resource -> 稳定 Asset -> 主站结算
  -> 私有授权播放/下载 -> 音乐历史与共享资产库
```

模型 ID 是 `channelID::modelKey`。服务端按有效主站模型、价格档和用户分组报价，前端不写死检查日价格。提交必须携带报价微积分和 nonce；服务端重新报价，变化返回 `music_quote_changed`。用户与 nonce 确定内部任务 ID；相同 nonce 的参数指纹改变被拒绝。并发重试复用主站任务及账单事务。

## 当前接通能力

| 协议操作                                  | 参数                                  | 未接通内容                                        |
| ----------------------------------------- | ------------------------------------- | ------------------------------------------------- |
| Suno `rhart-audio/suno-*/single`          | 简单描述、`make_instrumental: "true"` | custom 歌词、title、指定时长、人声、原生 WAV/FLAC |
| Mureka `mureka-ai/mureka-*/generate-song` | 原始多行 `lyrics`、独立风格 `prompt`  | 原生纯音乐开关、指定时长、人声、title、扩展操作   |

歌曲语言作为明确标注的风格偏好拼入 Mureka style，不声称上游原生 language 控制；不改写歌词或 UI 语言。Suno custom 是不同上游操作，本次未擅自增加。返回数量由真实结果决定；过滤图片/文本结果，音频时长采用实测毫秒。无假波形、假进度、默认 180 秒或付费封面。

协议依据包括 RunningHub 官方 [Suno single v5.5](https://www.runninghub.cn/runninghub-api-doc-en/api-448969329) 与 [Mureka v9 generate-song](https://pre.runninghub.cn/runninghub-api-doc-en/api-494859310)。Suno v6 仅回查旧简单任务，其他版本与参数组合未据此声称全部验收。

## 异步、归档与账务

- 创建的 QUEUED 仅表示已受理。供应商 ID 写入任务及调用日志，后续仅查询该 ID。重启恢复和暂时查询故障复用宿主分离轮询、退避及 48 小时策略。
- 归档失败保存加密 checkpoint；只重试下载、存储和资产登记。`recover-media` 不重新调用 create。已 ready 的前缀资源可在任务未终结时播放，不泄露上游 URL。
- 资产沿宿主 `materialize:task:index` 稳定键，保存模型、创作参数、上游 ID、输出序号、MIME、字节数和时长。前端不重复插入有宿主 storageKey 的资产。
- fixed_request 成功采用主站账单快照；其他计价与归档失败、退款、待核对沿宿主策略。播放、查询和下载不创建账单。旧后台测试恢复无原用户账单，不补扣费用。
- 旧测试恢复只接受管理员与原始 `admin_model_test/audio` 日志，固定内部 ID；缺少原供应商 ID 直接拒绝执行，防止恢复退化为重新付费生成。

## 插件生命周期

音乐模块 1.3.0 要求宿主 1.7.4。配置启停是运行时操作；代码、前端和 RunningHub 1.1.2 包升级需要构建、部署及重启，不承诺零停机热插拔。

启用、排空、停用、更新、卸载等状态，与平台准入和管理员审计在同一事务保存，失败不提前更新内存。排空阻止新任务；已有主站 worker、授权查询、归档、结算和历史继续。活动数量包含数据库中的主站音乐任务；排空完成后持久化停用。卸载只改变准入状态，保留配置、用户偏好、作品、资源、任务、账单与流水。

旧独立 key、URL、webhook 和价格配置保留为历史备份，拒绝新增写入；不再作为新任务的入口。保留旧历史和旧签名回调兼容路径，不重写旧账目。未证明旧独立 worker 的非终态记录可跨进程恢复，这部分不能视为已迁移；升级前需清点此类旧记录。

## 界面

桌面左创作、右作品；窄屏 Create/Library 切换。根据模型能力显示 Simple/Custom、歌词结构、风格和歌曲语言。切模型保留草稿，提交只组装兼容字段。作品按任务分组，多首分别播放下载；详情与卡片共用同一 Audio 状态，支持 seek、队列、音量、静音、媒体错误和重新授权。

前台与后台测试页均按用户恢复草稿；从模型目录进入测试页时，明确指定的模型优先。已完成作品的详情提供共享素材库管理入口，继续使用宿主既有的重命名、收藏、删除及项目关联能力，不新建音乐专用写接口。

音乐 React 文案自行国际化，动态区域禁止外部 DOM 自动翻译，保护价格、播放时间和作品原文。首次无偏好默认 English；保留既有语言。真实软键盘和听感验收的执行状态单独记录，不以桌面模拟或解码结果代替。

## 数据与回滚

没有新增数据库字段、表或 schema 版本；继续使用 Schema 81 的 tasks、账单/流水、resources、assets 和 system_settings。读历史不再 AutoMigrate。已存在的旧音乐表保持只读历史，新任务不写该表。

升级前备份同一时点的数据库、数据目录、`.settings-key`、配置和现行镜像/发布目录；先排空并核对旧独立音乐任务。固定前后端与 RunningHub 包的匹配版本。不得把本地测试数据库或渠道密钥复制到生产。

回滚应先停止接单并等在途主站任务终结，保留新资源、账单和任务，回切匹配的前后端与协议包。旧前端可能不展示新主站音乐历史，但通用任务和共享资产仍保留。不要通过删除新账单、反向迁移或恢复旧数据库覆盖已经结算的数据。若确需数据库恢复，必须使用匹配备份并另行核对备份之后的全部业务账目。

## 冲突与插件边界

正式版九处与 main 五十一处文本冲突逐项处理，保留双方意图。设置仓储保留 SupDance 事务锁和上游前缀查询；社交登录会话桥、音乐权限及路由、视觉引擎、Codex 连接器、外观配置和六语言插件保留。电商功能仍由后台显式开关控制，默认关闭。

## 验证与部署纪律

源码、测试通过、GitHub 推送、生产运行与真实收费业务验收分别记录，不相互替代。需通过项目默认推送门禁、前后端构建和真实页面检查。PostgreSQL 必须从当前生产备份恢复到隔离库，验证 78→81 迁移、插件配置和数据行数后，才能操作生产。

生产使用自有分支固定提交的源码构建，并沿用既有 PostgreSQL/Redis/独立 Agent 的 Compose。版本、提交 SHA、二进制/静态资源校验和、实际 bind mount 和数据库版本均需核验。Agent 源码在本次范围无变化，保持既有独立服务；不得改为失败时回退内嵌运行。

数据库升级后的回退必须停止写入，并恢复匹配旧程序的数据库备份及静态资源/二进制；只有镜像切换的第一阶段回退脚本不适用于本次迁移。付费生成、支付扣款和外部 OAuth 重授权未经本轮授权，不计入自动验收。

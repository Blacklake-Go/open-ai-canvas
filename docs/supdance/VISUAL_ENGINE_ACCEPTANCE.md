# SupDance Visual Engine V2.0 验收记录

## 当前结论

尚未完成最初规范的全部验收。此前将类型检查、7 个纯函数测试和 HTTP 200 等同于完整交付的结论已撤回。

本次范围是修复已安装版本的配置发布闭环，使用经过用户授权的临时管理员在真实应用验证。完成测试后删除该账号及其认证会话，恢复测试前的视觉配置内容。

## 本次修复

- API 使用宿主 http 信封解包和 Cookie 认证，对齐实际 bundle、overview、draft、publish、rollback 路径。
- 移除浏览器本地发布/回滚与伪造的初始化审计记录，服务端成为发布配置的权威来源。
- 每位管理员保存独立服务端草稿，草稿不影响公共 bundle。
- 发布和回滚写入配置、历史快照、管理员审计，并在同一个数据库事务中完成；失败保留稳定配置。
- 服务端生成新版本、记录真实操作者，校验预期版本以拒绝过期写入；第一次发布保存原始稳定基线。
- 运行时订阅 Router 状态而不覆盖 history，不依赖 Router 上下文；读取公共发布配置，失败恢复宿主样式。
- 默认跟随宿主深浅色偏好；管理后台保留宿主样式。停用时恢复原有 inline Token。
- 插件管理统一控制可用状态，停用后隐藏视觉引擎菜单并禁用编辑控制台。

## 验证范围

专项自动测试覆盖草稿隔离、真实 HTTP 调用、服务端拒绝保留草稿、回滚、非法配置拒绝、过期写入、审计失败整笔回滚、跨 Service 持久化、Router 外挂载及资源清理。

前端专项：12 项通过、0 失败、57 个断言；类型检查与生产构建通过。后端发布、权限、事务失败回滚及持久化专项通过。

## 已安装版本与真实页面验收

修复代码提交为 `0f7134f6`，已推送生产分支并安装到现有生产 Compose。宿主版本保持 `v1.7.4-supdance.2`，Schema 保持 78，未更换数据库和 Agent。后端健康信息 Commit 与代码提交一致，容器内二进制与发布文件 SHA256 一致，实际静态入口与构建入口一致。

安装方式是随宿主编译的集成版，不是已完成独立安装/卸载验收的插件包。服务器保留原配置指针备份与旧发布文件。

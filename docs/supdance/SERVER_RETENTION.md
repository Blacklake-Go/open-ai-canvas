# 线上磁盘定期清理策略

线上使用服务器本地 `supdance-retention.timer`，每日台北时间 03:30 运行，不依赖桌面应用在线。实现和操作命令见 [保留工具](../../tools/supdance/retention/README.md)。

每次先检查站点和固定回滚材料，生成并完整解析主站及 ONE 数据库备份，再执行保留期清理。完整后端数据与 ONE 上传文件每周备份。清理成功或失败都会进行结束健康检查并写入 root 私有 JSON 报告。失败、部署发生变化或备份损坏时返回失败；磁盘达到 85% 时返回告警，不放宽删除边界。

| 内容 | 保留规则 |
| --- | --- |
| 本工具管理的每日数据库备份 | 至少最近 7 组，且至少 7 天 |
| 本工具管理的每周完整数据备份 | 至少最近 2 组，且至少 14 天 |
| 已退出的应用演练容器和已识别的生成副本 | 至少 7 天；不处理数据库或 Redis 容器 |
| 旧 Web 发布和无引用应用镜像 | 至少 14 天，每类还保留最新两个 |
| 当前运行引用与固定可用回滚材料 | 不按年龄删除 |
| 数据库目录、用户素材、所有 Docker 数据卷及原始历史数据库备份 | 不参与产物清理 |

对未知归档不凭名字或大小猜测删除资格。新的纯构建产物可以通过 `--register` 登记，仍须通过数据内容、挂载和进程引用保护检查。固定回滚清单与校验值在服务器私有策略文件中维护，更新应用版本后应复核。其他旧数据库备份 cron 和素材回收站任务属于独立策略，本工具不调用或修改。

上线验收包括：边界与保留数量单元测试、systemd 单元校验、真实服务执行、专用过期纯文本产物的删除验证，以及真实站点、前端脚本、数据库就绪和服务状态检查。不会用恢复旧数据库覆盖线上新交易来验证回滚。

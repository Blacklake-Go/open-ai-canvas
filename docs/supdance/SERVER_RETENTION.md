# 线上磁盘定期清理策略

线上使用服务器本地 `supdance-retention.timer`，每日台北时间 03:30 运行，不依赖桌面应用在线。实现和操作命令见 [保留工具](../../tools/supdance/retention/README.md)。

定时器、回滚保护策略和运行报告均独立于应用发布目录。专用安装器重复运行时保留已有策略及 systemd 单元，并通过安装指纹防止静默接受覆盖；每次清理前由 systemd `ExecStartPre` 检查。普通 Compose、Web 静态发布和 Host Updater 不负责更新这些宿主配置。测试同时覆盖重复安装保留自定义设置、配置被改后的拒绝运行，以及真实 Web 发布脚本的连续两次发布。

每次先检查站点和固定回滚材料，生成并完整解析主站及 ONE 数据库备份，再执行保留期清理。完整后端数据与 ONE 上传文件每周备份。清理成功或失败都会进行结束健康检查并写入 root 私有 JSON 报告。失败、部署发生变化或备份损坏时返回失败；磁盘达到 85% 时返回告警，不放宽删除边界。

| 内容 | 保留规则 |
| --- | --- |
| 本工具管理的每日数据库备份 | 至少最近 7 组，且至少 7 天 |
| 本工具管理的每周完整数据备份 | 主站保存至私有 COS，保留历史异地备份，至少满足最近 2 组且至少 14 天的保留要求 |
| 已退出的应用演练容器和已识别的生成副本 | 至少 7 天；不处理数据库或 Redis 容器 |
| 旧 Web 发布和无引用应用镜像 | 至少 14 天，每类还保留最新两个 |
| 当前运行引用与固定可用回滚材料 | 不按年龄删除 |
| 数据库目录、用户素材、所有 Docker 数据卷及原始历史数据库备份 | 不参与产物清理 |

对未知归档不凭名字或大小猜测删除资格。新的纯构建产物可以通过 `--register` 登记，仍须通过数据内容、挂载和进程引用保护检查。固定回滚清单与校验值在服务器私有策略文件中维护，更新应用版本后应复核。其他旧数据库备份 cron 和素材回收站任务属于独立策略，本工具不调用或修改。

Host Updater 的当前回滚归档从状态文件动态读取并保护，正在更新时停止清理。人工回滚脚本及其依赖归档也固定保护。上线审计发现历史更新器指针失效时，先保存原记录再撤销无效入口；不能把新的备份伪装成该历史版本的恢复点。

主站当前部署配置和发行备份中的回滚配置也纳入保护。每日备份可以在历史回滚材料校验失败时继续生成，清理仍会停止并记录失败。独立的发布后定时任务只清理超过 7 天、且不在最新两组中的可重建后端 Docker 构建上下文。发布目录、回滚归档及镜像仍由每日保留策略处理。

### PR #29 的异地归档

两份后端恢复归档及其元数据保存在私有 COS。迁移时逐一下载、解密并核对原始 SHA-256，验证通过后才移除两份本机大文件。原备份目录保留恢复说明、校验清单和 `OFFSITE-ARCHIVES.json`。加密密钥在站点服务器和维护设备上独立保管。

需要演练或恢复时，在独立恢复目录逐一取回两个归档，再按原备份的 `BACKEND-DATA-RESTORE.txt` 操作。恢复命令会验证私有访问状态、文件长度、解密结果的 SHA-256 和归档结构，并拒绝覆盖已有文件。

```bash
sudo /usr/local/sbin/supdance-restore-offsite-pr29 backend-data.tar.zst /path/to/recovery/backend-data.tar.zst
sudo /usr/local/sbin/supdance-restore-offsite-pr29 backend-data-plugin-refresh.tar.zst /path/to/recovery/backend-data-plugin-refresh.tar.zst
```

### 每周全量备份

主站启用 `weekly_offsite` 后，每周将主站后端数据和两处 ONE 上传目录分别打包加密到私有 COS。每份归档完整读回并验证解密、压缩完整性和 SHA-256 后，才发布本机和 COS 的恢复清单。每次只暂存一份加密文件，单份上限 4 GiB，并给系统盘保留至少 3 GiB 余量。数据库每日备份继续保留在本机。每日清理以 COS 对象的可读性、私有访问状态和长度检查作为异地备份校验门槛，云端历史备份不随本机轮换删除。

旧周备份可通过 `retention.py --apply --migrate-weekly` 迁移。下载到隔离恢复目录前，先从服务器的托管备份目录或 COS 私有 `ops-backups/supdance-prod/weekly/manifests/` 前缀取到相应清单。恢复命令会重新读回完整内容并核对哈希与压缩完整性。

```bash
sudo python3 /usr/local/lib/supdance-retention/weekly_offsite.py \
  /path/to/weekly-manifest.json ARCHIVE_NAME.tgz /path/to/recovery/ARCHIVE_NAME.tgz
```

上线验收包括：边界与保留数量单元测试、systemd 单元校验、真实服务执行、专用过期纯文本产物的删除验证，以及真实站点、前端脚本、数据库就绪和服务状态检查。不会用恢复旧数据库覆盖线上新交易来验证回滚。
